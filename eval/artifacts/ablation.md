# 检索消融实验

评估集：`data/eval/golden.jsonl`，共 300 题，五桶各 60 题。知识库：`data/knowledge/` 6 篇文档，切分后 70 个 chunk。

四种策略跑的是同一批题、同一个检索器（`MockEmbedder` + `BM25` + `MockReranker`，
全离线、确定性）。多轮题在检索前统一经 `CoreferenceResolver` 做指代消解，
该步骤为四种策略共用，不计入任何一路。

## 怎么读这张表（口径限制）

1. **不要把绝对分当成线上效果**。知识库只有 70 个 chunk，`fusion_top_k=10` 的候选池已经覆盖全库的 1/7，Recall@5 天然偏高；换成上千块的库，同一套题的数字会明显下降。

2. **dense 这一路是被 mock 拖累的**。`MockEmbedder` 是确定性哈希词袋，没有真正的语义泛化能力，所以 dense 输给 BM25 只能说明「在这个 mock 环境下词面匹配更强」，不能说明真实向量模型也这样。

3. **拒答准确率只在 hybrid_rerank 上可读**。dense / hybrid 的分数是 RRF 的相对分（每条除以本查询最高分），排第一的那条恒等于 1.0，于是 `top_score` 永远大于阈值 0.35，拒答判据在这两条策略上恒判「不拒答」。sparse 能拿到 0.98 是因为部分拒答题在 BM25 上真的一条都匹配不到（返回空 → 最高分 0）。**这是指标口径与打分口径不匹配，不是检索质量问题**：`evaluate_strategy` 里的 `top < 0.35` 代理判据只对「绝对分」策略成立。

4. **hybrid_rerank 的绝对分偏乐观**。评估集生成时做过一次标定（`eval/build_golden.py --check` 要求每条标注在 hybrid_rerank 下至少有一个相关块落在前 5），所以它是唯一被对齐过的策略。策略之间的**相对**差异不受影响 —— 同一批题对四条路是同等难度的。

5. **Precision@5 低不是检索差**。240 道召回题里有 99 道标了 2～3 个相关块，其余只标 1 个，5 个返回位置里必然有 4 个「未标注」——分母决定的上限。读这张表时看 Recall 和 MRR，别读 Precision 的绝对值。
